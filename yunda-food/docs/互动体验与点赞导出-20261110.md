# 互动体验与点赞、导出范围（2026-11-10）

本轮五件事都来自同一张截图反馈：卡片图片下方空一截、"只看同乡"下面还挂着一行小字、评价一多就把详情页拉得很长、详情页方框只有"收藏 / 再来一次"没有点赞、导出只能选自己的一亩三分地。逐条落地如下。

## 一、卡片缩略图贴满卡片高度

`.food-media` 原来是死的 `88×88` 方块，而卡片高度由右侧文字（标题 / 店名 / 地点 / 口味 / 作者行）撑到 115px 左右，图片贴顶放，下面自然空出一条 27px 的空白带。

```css
.food-media{flex:0 0 88px;height:88px;border-radius:7px}          /* 紧凑列表、格子视图继续用它 */
.food-card .food-media{align-self:stretch;height:auto;min-height:88px}  /* 首页卡片改成竖版拉满 */
.food-card .food-media img{object-position:50% 55%}
```

宽度仍是 88px（横向不挤压文字），高度跟着卡片内高走（实测 88×115，与内高 115px 完全对齐，上下留白 0）。`object-fit:cover` 不变，`object-position` 略微下移到 55%，裁切时保住盘子和主食那一块，不至于把菜顶裁掉。`.food-row`（52×52）与 `.food-tile`（96 高）各有自己的覆盖规则，没被这条带跑。

## 二、"只看同乡"去掉副标题并重新定尺寸

`<small>同省同市</small>` 删掉，按钮从"两行字"变成"一行字"，尺寸重定为 `min-height:30px;padding:5px 12px;font-size:12.5px`，与 `⌘ 筛选` 同高同排，`.hometown-toggle small` 的样式规则一并删除。

顺带发现一个既有排版问题：手机上这行本来就装不下——排列切换 144px + 同乡 76px + 筛选 66px + 间距 ≈ 300px，而标题"同学的实吃推荐"占掉 112px 后只剩 242px，所以过去一直是"前两个一行、筛选掉到第二行"的折断状态，只是被那行小字盖住了。这轮给标题加了 `home-heading` 修饰类，把工具行整体放到第二行左对齐：

```css
.section-heading.home-heading{flex-wrap:wrap;row-gap:9px}
.home-heading .home-tools{flex:1 1 100%;justify-content:flex-start}
```

现在 320/360/390px 三档都是"标题一行 + 卡片/紧凑/格子 + 只看同乡 + 筛选 一行"，工具行高 30px，比原来折断的 67px 还矮。

## 三、评价超过三条自动折叠

详情页新增 `reviewsOpen` 状态，默认渲染 `reviews.slice(0,3)`：

- 3 条以内：完全不变，连折叠条都不出现；
- 超过 3 条：列表底部出现虚线折叠条「展开全部 N 条评价 · 还有 N-3 条」（`aria-expanded` 同步），点开显示全部，按钮变成「收起评价 · 只看最新 3 条」。

折叠只影响渲染，不影响"X 分 · N 人"的统计口径——均分和人数仍然按全部公开评价算。

## 四、详情页新增点赞，收藏与"下次想吃"合一

`detail-actions` 从两列两按钮改成"点赞 / 收藏 一行 + 再开盲盒 占满一行"：

| 按钮 | 语义 | 实现 |
| --- | --- | --- |
| 点赞（手形图标 + 数字） | **纯计数**，再点一次取消 | 新动作 `likeFood`，集合 `xsyj_food_likes` |
| 想吃 · 收藏 / 已收藏（心形） | 就是"下次想吃"，与"我的收藏"同一份数据 | 复用既有 `favorite` 动作与 `toggleFavorite` |
| ▧ 再开盲盒 | 原样 | 不变 |

图标照 bilibili 的手形点赞画的内联 SVG（未赞描边、已赞填充），不引外部图标库。样式沿用站内 secondary 按钮的画风：未赞浅蓝底、已赞实心蓝底白字；收藏未选是浅蓝、已选是站内红实心，两者都带 `aria-pressed` 回显。

服务端只做计数，不写互动消息（避免点赞刷屏），计数永远不为负：

```js
// service.cjs
case 'likeFood':{…约束同上：必须是 published 且对当前用户可见…
  await f('toggleFoodLike',{itemId:p.id,liked:p.liked}); likedItems=undefined; return food(await f('getItem',{id:p.id}))}
// native/food/index.js
if (payload.liked && !old) { 写 likes 记录; likeCount = current + 1 }
else if (!payload.liked && old) { 删 likes 记录; likeCount = Math.max(0, current - 1) }
```

`food` DTO 新增 `likeCount`（`Math.max(0,Number(row.likeCount)||0)`）与 `liked`（按 `xsyj_food_likes` 里当前 UID 的记录判定，与 `favorite` 各自一份缓存，互不污染）。演示仓储同步加了 `likeFood` 动作与 `likedFoods` 字段，本地演示也能点赞、刷新后保留。

## 五、导出新增"全部美食"并排在最前

`ExportPage` 的 `Scope` 从 `'mine'|'favorites'` 扩成 `'all'|'mine'|'favorites'`，默认落在 `'all'`，按钮顺序即 `全部美食 N / 我的投稿 N / 我的收藏 N`，`SCOPES` 常量统一顺序，`sheetNameOf()` 与 `exportFileName()` 一并支持。

- 数据源：`repository.foods()`，也就是网页首页实际加载的公开推荐，不含下架与待审内容；
- 原有筛选（关键词 / 分类 / 校内校外）全部沿用，全选仍按筛选结果走 `EXPORT_LIMIT=2000`；
- 文件名：`小食云记-全部美食-20261110.xlsx`，工作表名「全部美食」；
- 有一处诚实的提示：`listPublishedItems` 单次取 100 条，若公开推荐达到 100 条，导出范围也就到这 100 条，页面会显式提示"更多内容请按分类分批导出"。当前线上公开推荐 4 条，离这个上限还很远。

## 七、没动的边界

- 待审**评价**的可见性仍未按 `reviewTag` 过滤：别人的待审评价此刻仍能看到正文并计入均分（推荐/经历/话题/楼层都已按"非 approved 只有作者与管理员可见"处理）。这是上一轮就记录在案的遗留项，改动会让评价在通过审核前从公开页消失、均分也随之变化，需要单独确认，本轮未动。
- 点赞是"计数"语义，不产生任何互动消息与待办角标；如果以后想给作者推"有人赞了你的推荐"，需要先在通知中心加一种类型，避免和审核提醒混在同一个数字里。
- "全部美食"导出覆盖的是网页实际加载的公开推荐（单次最多 100 条），不是数据库全量；要突破需要加一个分页导出的服务端动作，本轮没做。
- 仍未在实体机/微信内置浏览器上逐机型验证折叠与点赞的触感与高度。
