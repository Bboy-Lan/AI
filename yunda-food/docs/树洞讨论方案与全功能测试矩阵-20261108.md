# 树洞扩展方案与验收矩阵

用户明确要求审核后直接落实Web讨论，无需再次选择环境或重复部署授权。保留当前奶油底、蓝色/黄色按钮、卡片、四项底栏及430px画布；原小程序/旧H5/冻结参考只读。

## 审核结论与取舍

采用现有经典云函数+异步主题/楼层：相比独立即时聊天无需额外长连接服务；相比只做本机帖子可实现跨账号真实发布与管理。树洞一级分为黑榜避雷与同乡留言。黑榜保留事实消费经历、分类、日期、先审后发、版本检查、点赞/举报/撤回，讨论作为独立类型，不把同乡自填信息当成认证或私聊。

已发现黑榜缺口：客户端未明确标注/本地校验问题类别、经历正文与消费确认；管理举报和消息只取首个20条分页且UI未接后页；保存/举报回执只识别请求编号，不核对内容是否一致。现有真实32项仅覆盖部分黑榜主流程。全功能验收脚本还直接修改共享公告，缺少并发保护下的原值恢复，新验收应改用隔离模拟写入公告+线上只读验证，避免覆盖真实公告。

## 最小完整业务

- 主题：分类（同乡交流/校园生活/吃喝吐槽）、标题2～60字、正文2～2000字、最多3张本人图片；广场、同乡、我的发帖、我的回复；每页20条，明确加载更多。
- 楼层：登录且资料完整才能发；主题内事务递增楼层，支持回复某楼、稳定页码、消息跳转指定楼层。重试不重复建楼，隐藏/撤回留占位不重排；主题撤回后不再接受新楼层。正文2～1000字。
- 治理：作者修改/撤回本人主题、撤回本人楼层；不能借编辑恢复管理员隐藏。用户可举报主题或楼层并保留快照；管理员带原因隐藏/恢复、处理举报、审计留痕。每日主题/修改5次、回复60次、举报20次，重复请求不消耗额度；访问和写权限由服务端运行时UID决定。
- 消息：楼主/被回复人收到去重提醒，用户可定位原话题及楼层、已读/删除/清理；管理员举报待处理数量进入既有角标。用户治理内进入讨论治理；普通用户不能调用管理接口。
- 数据：仅新增xsyj_forum_topics/replies/reports/notifications/meta/audit六个ADMINONLY集合及必要索引；复用原头像/图片私有上传路径；不改礼金簿/全局认证/套餐。公开DTO不包含真实UID或邮箱。
- 草稿与失败：主题/回复输入保持，网络失败保留内容及同一提交编号；标题/正文/类别必填缺失时不提交，不自动丢弃草稿。
