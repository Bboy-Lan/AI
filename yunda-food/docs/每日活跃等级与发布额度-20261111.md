# 每日活跃等级、每日推荐发布额度、管理员覆写与推荐卡响应式

日期：2026-11-11。本轮只改本工程 `D:\Desktop\小食云记-新网页版`，原小程序、旧 H5、冻结参考与礼金簿资源保持只读。

## 一、需求对照

| 要求 | 落地位置 |
|---|---|
| 新用户默认「小吃货」、每日 1 条 | `daily-level-rules.json` 第一档；缺字段旧用户按 `streak=0` 回落同一档 |
| 连续签到累计活跃天数、同日不重复 | `context` 每次加载幂等签到；`daily-activity.cjs` 的 `checkIn` 读后写，同日早退不写库 |
| 1–6 / 7–13 / 14–20 / 21–27 / 28+ 天五档称号与 1/2/3/3/3 条额度 | 规则表唯一来源，前端 `src/domain/daily-level.ts` 与服务端 CJS 同读一份 JSON |
| 中断从 1 天重新累计 | `streakAfter(lastDay, streak, day)`：`lastDay+1===day` 才 +1，否则回到 1 |
| 每日额度按 Asia/Shanghai 自然日 | `chinaDay()` 固定 UTC+8 偏移（无 DST），`submissionDay` 沿用原有统计字段 |
| 额度由服务端强制、前端只展示 | `native/food/index.js` 的 `submitItem` 调 `dailyActivity.assertQuota(id, profile)` 替换原硬编码「每天 3 条」；前端只显示剩余额度、耗尽提示与禁用按钮 |
| 耗尽后禁止提交并提示称号/明日额度/升级条件 | 规则表 `messages.exhausted` 模板，服务端生成文案后直接由 `rpc` 错误回显 |
| 管理员用户详情页「每日发布额度」管理区 | `AdminProfilePanel.tsx`：当前称号、连续活跃天数、等级默认额度、今日已发布/剩余、实际生效额度、明日额度、覆写失效日、设置人/时间/原因、历史记录 |
| 自定义额度 + 原因 + 可选失效日期；取消覆写立即恢复 | `adminSetDailyQuota`（`set` / `clear`）；取消写 `{active:false,...}` 而不写 `null` |
| 覆写优先于等级额度，保留设置人/时间/原因/失效时间与历史 | `dailyQuotaOverride` 存 `xsyj_profiles`，审计写 `xsyj_events`（`type=daily_quota_override`），`adminDailyQuotaDetail` 返回最近 10 条 |
| 后端权限校验，普通用户不能读改他人覆写 | `service.cjs` 的 `admin*` 统一拦截 + 模块内 `requireAdmin` 双保险；`context` 只回自己的等级视图，不含设置人与历史 |
| 旧数据兼容 | 不新建集合、不迁移、不批量写历史资料；缺字段按「小吃货 + 1 条/日」 |
| 个人页称号/连续天数/升级进度/发布权益 | `CloudMe` 的 `.level-card`（称号、每日额度、进度条、升级条件、覆写说明） |
| 推荐卡作者附近紧凑称号标签，无作者不留空白 | `RoleBadge` 新增 `title` + `.level-badge`；`FoodCard`/`FoodTile` 展示，`FoodRow` 保持紧凑不显示作者行 |
| 文案统一，不用 Utral | 全项目 UI 源码无该拼写，测试与浏览器验证均有守卫 |

## 二、推荐卡响应式

- **价格单元**：三视图共用 `PriceUnit`，`.price` 改 `display:inline-flex` + `white-space:nowrap` + `flex:0 0 auto` + `min-width:58px`，`.price-unit` 由 `display:block` 改 `inline`；金额与 `/人`、`/份` 不再折成两行，标题可收缩/两行省略。
- **列表卡**：`.food-title-row` / `.food-row-title` / `.food-card .food-author` 移除 `space-between`；`.food-row-body` 改纵向流式 `gap:4px`、店名 `margin:0`，标题与店名间距稳定 4px。
- **双列卡**：统一「图片（96px 固定）/标题（2 行 + `min-height:2.9em`）/店名·推荐人（单行省略）/价格/评分」五段；`.food-grid-view` 用 `repeat(2,minmax(0,1fr))` + `align-items:stretch`，`.food-tile{height:100%}`、`.food-tile-body{flex:1}`，无图/无评分不改变卡片节奏；`.home` 底部留白提到 84px 兜底导航与发布按钮。
- 所有规则仍保持「一行一条」，避免破坏既有的 `\{[^}]*\}` 源码守卫。

## 三、兼容与数据策略

不新建集合：签到字段落在 `xsyj_profiles`（`activityLastDay` / `activityStreak` / `activityUpdatedAt`），覆写落在同一文档的 `dailyQuotaOverride`，审计落在已有 `xsyj_events`，今日已发仍按 `xsyj_food_items.ownerOpenId + submissionDay` 统计。因此无需预建集合或索引，也没有任何批量数据迁移；真实用户资料只在本人签到时被追加字段，原有昵称、头像、家乡、归属不变。

规则表与文案模板位于 `server/classic/xsyj_web_v1/daily-level-rules.json`；云函数是 CJS 不能 import TS，所以纯函数保留前后端两份镜像，由 `tests/daily-level.test.ts` 逐项比对输出，规则本身只有一份。

失效时间按 Asia/Shanghai **自然日**粒度：到期当天仍有效，次日起恢复等级额度。覆写值允许 0（禁止发布）到 20。

## 五、未覆盖风险与边界

- 未做真实 CloudBase 云端端到端联调前，`db.serverDate()`、事务/并发在真实环境的表现以线上为准；主 `native/food/index.js` 因顶层 `wx-server-sdk` 副作用无法直接 require，额度链路用「可注入 CJS 模块实跑 + 源码守卫」覆盖。
- 签到是「读后写」幂等：同日并发重复写不会让天数多涨（已测），但不是事务/CAS，仍有极小概率多一次无意义写入。
- 演示态为满足既有「只读页面不写回存储」约定，签到只在写动作时持久化；纯浏览跨天不会累积连续天数（真实服务端不受影响）。
- 失效时间只支持日期，不支持小时级；编辑已有投稿不消耗当日额度。
- 紧凑列表视图为保持流式紧凑不显示作者/称号；管理员身份标识「♛ 吃货大王」与等级称号是两套文案。
- 未测 iOS/Android 真机与微信内置浏览器；桌面 Chromium 多视口不等于真机。
