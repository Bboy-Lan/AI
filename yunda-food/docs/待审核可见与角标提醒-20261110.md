# 待审核只对作者可见 + 红色数字角标提醒（2026-11-10）

本轮按五条口头需求落地，均在本机改完、单测与浏览器验收通过，并已发布到两个公开入口后读回验证。

## 一、需求与对应实现

| 需求 | 实现 |
| --- | --- |
| 管理员发布的帖子等默认是已审核状态 | 服务端按运行时身份判定：`review-policy.resubmit(null, isAdmin)` 对管理员直接给 `approved`；推荐、消费经历、树洞话题、楼层回复、评价五类一致。真实云端逐类验证（推荐、经历、话题）均返回 `approved`。 |
| 有用户上传等操作时互动消息要及时提醒，用与用户相同的红色醒目数字 | 底部导航、我的页「互动消息」、用户治理「待审核」、集中审核台统一使用 `CountBadge`：站内红 `#e94e3c`、白字、胶囊、>99 显示 `99+`、0 不渲染。用户看未读、管理员看未读 + 待办，数字取自同一份 `notificationSummary`。 |
| 待审核内容只有该用户自己能看见 | 新增统一判定：`reviewTag !== 'approved'` 且不是作者、不是管理员，则不出现在公开列表、详情返回空、不能收藏、不能评分。推荐、树洞话题/楼层、消费经历（原本就是先审后发）全部适用。 |
| 这些操作都要给管理员提示，便于及时审核 | 管理员 `pendingCount` 纳入集中审核台的全部待审内容（推荐/经历/话题/楼层/评价）+ 举报 + 反馈；回到前台 8 秒节流刷新，切回页面即更新角标。 |
| 首页小卡片不要蓝色推荐理由，移到详情 | 抽出 `reasonItems()`/`matchScore()`：首页只用分值排序、不渲染文案；详情页在标签下方以浅蓝胶囊逐条展示「同乡推荐（家乡自填）」「符合你的辣度」「你收藏过同一主食」等。卡片不再为理由预留高度。 |

## 二、可见性规则落在哪一层

- `server/classic/xsyj_web_v1/service.cjs`：`reviewHidden(row)` 一处判定，`foods`、`food`、`myFavorites`、`favorite`、`saveReview`、`publicProfile` 共用；作者本人与管理员不受限，无 `reviewTag` 的老记录按发布状态推导为已审核，照旧公开。
- `server/classic/xsyj_web_v1/forum.cjs`：`hiddenFrom(row, identity)` 过滤话题列表；话题详情对非作者非管理员返回「这条话题暂不可访问」；楼层正文对他人置空并标记 `reviewPending`，楼层号保留，页面提示「这层回复待管理员审核，仅作者本人可见」。
- 老数据不需要迁移：判定只看 `reviewTag`/`status` 的现值，历史 `pending` 记录在本次上线后自动从公开视图消失，作者与管理员的审核台仍能看到并处理。
- 演示仓储（`src/demo/repository.ts`、`src/demo/forum.ts`）与真实服务端同口径，三组 demo 入口的表现与线上一致。

## 三、数字口径

`notificationSummary` 的管理员 `pendingCount` = 集中审核台待审（五类内容）+ 待处理举报（推荐/经历/树洞）+ 未读反馈。管理员的角标因此一定 ≥ 审核台的待审核数，点进去不会看到"数字对不上"。普通账号的 `pendingCount` 恒为 0，角标只反映自己的未读消息。

## 五、边界与未做

- 评价（评分）文本本轮**没有**对他人隐藏：评分本身已计入公开均分，只隐藏文字会出现"5 人评分但只列出 3 条"的错位。评价仍带审核标签，待审核徽章只对作者与管理员显示。
- 待审核内容被隐藏后，作者的"我的投稿/我的发帖/我的回复"照旧可见，首页与公开列表看不到；没有任何"审核中"的公开占位，因此他人不会感知到有一条记录正在排队。
- iPhone/Android/微信实体机的角标渲染与后台恢复时机未逐机型验证；回到前台刷新依赖 `visibilitychange`，桌面 Chromium 与移动视口模拟均正常。
- 管理员的角标是"待办总数"，不是"待审内容数"；两个数字不一致是设计选择（举报与反馈也需要处理），审核台入口另有独立数字。

## 六、同日追加：管理员用户列表改为紧凑卡片

原来「用户治理 → 用户」把每个用户渲染成一整宽记录卡：昵称、省市各占一行，状态标签再占一行，右侧一大片空白，用户一多就要滚很久。

现改为固定摘要卡：左侧 34px 圆形缩略头像（无头像回落「食」），右侧上排昵称、下排「省市 + 状态标签」；每行两个（`repeat(auto-fill,minmax(158px,1fr))`，390px 下卡片 165×58，430px 下 197×58），整卡可点开用户资料面板。状态标签三色：正常（绿）、已封禁（红）、限制发布（琥珀）。省市长名按省略号收敛，标签不压缩。「小黑屋」沿用同一套卡片。

顺带修掉一个切换标签的旧问题：切到「用户」的瞬间，列表里还是上一个标签的数据（推荐行没有 `uid`），既会出现 React key 警告，也可能短暂显示错误字段。现在记录行带上所属标签（`rowsFor`），列表与空态只认当前标签的数据；切页不再闪现旧内容，`consoleErrors` 回到 0。
