# 排布方式、管理员私信与“点开即已读”（2026-11-10）

本轮三条需求：美食页可换排布方式；管理员能私信用户、用户只能看和回；互动消息点开就算已读，而且已读/未读要一眼看清。

## 1. 美食页排布方式

`src/domain/discovery.ts` 新增纯函数 `sortFoods(items, mode)` 与 `SortMode='recommend'|'likes'|'newest'|'rating'`：

- **推荐顺序**：不打乱仓储/筛选原有顺序（默认口径，和以前完全一致）。
- **点赞最多**：按 `likeCount` 从高到低；同赞数按发布时间新的靠前，再按原顺序兜底。
- **最新发布**：按 `createdAt`（缺失时退回 `updatedAt`，再缺失记 0）从新到旧。
- **评分最高**：**有评价的排在没有评分的之前**，再比均分、评价人数、点赞数，最后按发布时间兜底。均分还是 1 位小数，口径与详情页一致。

首页 `.home-tools` 下面新增一行 `role="group" aria-label="排布方式"` 的胶囊按钮（推荐顺序 / 点赞最多 / 最新发布 / 评分最高），选中态沿用站内蓝 + 1px 硬阴影。选择写 `localStorage:xsyj-home-sort`，刷新与切页都保留。排序在 `filterItems(...)` 之后再执行，所以搜索、只看同乡、分类筛选都不受影响。顺带在卡片 `.food-meta` 尾部补了 `· 赞 N`（只在有赞时出现），换到点赞排布时能看出凭什么这么排。

排序全部是稳定排序：同一份数据反复渲染顺序不变，不会出现"每刷新一次卡片位置就跳一下"。

## 2. 管理员私信

**只有一个方向能发起**：管理员找用户。用户不能新建对话，只能读自己那条并回复。

### 数据与服务端

新集合 `xsyj_direct_messages`（ADMINONLY，客户端不直读），字段 `userUid`（对话归属用户）、`senderUid`、`fromAdmin`、`body`、`userRead`、`adminRead`、`createdAt`，另有 `userHidden`/`adminHidden` 预留软隐藏。

6 个动作（`native/food/inbox.js`）：

| 动作 | 权限 | 说明 |
| --- | --- | --- |
| `myDirectMessages` | 登录用户 | 自己那条对话，按时间正序，`read` 取 `userRead` |
| `adminDirectThreads` | 管理员 | 按用户聚合的对话列表，带最后一条、时间与未读数 |
| `adminDirectThread` | 管理员 | 单个对话的完整消息 |
| `sendDirectMessage` | 管理员 | 发起私信；不能发给自己 |
| `replyDirectMessage` | 登录用户 | 管理员写回目标用户，普通用户只能写进自己那条 |
| `readDirectMessages` | 登录用户 | 管理员清 `adminRead`，用户清 `userRead` |

几个刻意的设计：

- **openid 不出服务端**。客户端只传主页 `profileId`，服务端 `profileRow()` 解析出 `ownerOpenId` 再读写；对话 DTO 只返回 `{id, body, fromAdmin, read, createdAt}`。云端验收里专门断言了 `adminDirectThread` 的返回不包含对方 UID。
- **越权写不进去**。普通用户调 `replyDirectMessage` 时服务端直接忽略传入的 `profileId`，用自己的运行时 UID；验收用"伪造别人的主页编号"实测过，对方对话里没有出现这条。
- **未读并入消息汇总**。`notificationSummary` 增加 `directSummary`：用户算"管理员发来且未读"，管理员算"用户回复且未读"，计入现有红色角标。封禁用户仍可读 `myDirectMessages` / `readDirectMessages` / `replyDirectMessage`（管理员说明要能看到、能回），其余动作照旧被拦。
- **幂等**。带合法 `clientRequestId` 时用 `dm_ + hash(thread:request)` 作为文档 ID，网络重试不会写出两条。
- **不依赖复合索引**：取回后在内存里排序；集合尚未创建时按空对话处理，避免新集合拖垮整个消息汇总（首次部署就是这样暴露出来的）。

### 前端

- 消息页新增「私信」分组（`#/messages?mode=direct`）。管理员看到左侧对话列表（头像、昵称、最后一句、红色未读数），点开即读；用户侧没有对话列表，只有"只有管理员可以主动发起私信"的说明 + 历史消息 + 回复框。
- 气泡按发送方分左右：管理员在右、用户在左（各自视角），每条带发送方与日期。
- 管理员用户资料面板（`AdminProfilePanel`）新增「发私信」按钮，跳到 `#/messages?mode=direct&user=<profileId>` 并直接打开这位用户的对话。
- 演示环境补了种子私信：管理员案例里有与阿岚同学（含 1 条未读回复）、云朵同学的两条对话；学生案例里有一条管理员未读私信，方便直接看到未读样式。

## 3. 互动消息点开即已读 + 标签更醒目

- 点「查看原投稿 / 查看原经历 / 查看话题」时，先 `mutate('read', id)` 再跳转；
- 点「展开对话 / 展开处理」时同样先标已读，只有**收起**不重复标记；
- 用户反馈面板的「补充 / 回复」展开同理（`FeedbackPanel` 内部处理）；
- 「标为已读」按钮保留，用于不想跳转只看一眼的场景。

未读/已读标签从原来的灰色小字改成胶囊 `.read-tag`：已读是米白底细描边，未读是站内红底白字并带 1px 硬阴影，和导航角标同一套红。反馈分组有「待处理/处理中/已处理」自己的状态标签，所以只在评论与收藏、避雷参考这两组套用新胶囊，避免语义混在一起。

## 已知边界

1. 单条对话最多读 100 条、管理员对话列表最多 200 行，没有分页与"加载更多"；目前使用量远低于这个量级，真到上限需要补游标。
2. 私信只有文字（2–300 字），不支持附件、图片、撤回、删除；用户侧也没有"已读回执"以外的状态。
3. 私信不触发邮件/短信/微信推送，只在站内红色角标提示；管理员没上线时用户回复不会提醒到人。
4. 「私信」分组与其它消息分组一样 15–10 秒轮询，不是实时长连接。
5. 排布方式只作用于首页当前列表（服务端单次最多 100 条），不是数据库全量排序。
6. 未在实体机/微信内置浏览器验证气泡高度、键盘顶起与输入框体验。
