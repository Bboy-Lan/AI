# 定位与导航：从「能选个点」到「选得准、找得到」（2026-11-10）

本轮按"完善网页版的定位功能，参照小程序版本的实现逻辑，更方便用户使用"落地。小程序那边是 `wx.chooseLocation()` + `wx.openLocation()`：选点后自动带回地点名、保留手填文字地址、可清除、可预览导航。网页版此前只有一个 Leaflet 弹窗（纯 OSM 底图 + 浏览器定位 + 手填经纬度），详情页也只有一个跳 `openstreetmap.org` 的按钮。本轮把这条链路补齐，同时把坐标系这件事一次性理清。

## 一、需求与对应实现

| 用户感受 | 实现 |
| --- | --- |
| 地图上得看得懂中文地名 | 选点弹窗默认用高德底图（`webrd0{s}.is.autonavi.com`，中文标注、国内直连），失败 4 块瓦片自动切 OSM；OSM 也不通时提示"仍可粘贴位置或手填经纬度"，选点与保存不受影响。底图可手动切换。 |
| 点一下就能定位，别只给个输入框 | 点地图任意位置落红点，红点可拖动微调；`◎ 用我的位置` 走 `enableHighAccuracy` + 12 秒超时，成功后显示"± 精度 米"，越界时提示"当前位置不在昆明服务范围"。未选点时不落红点，避免"尚未选点却已经有个点"的错觉。 |
| 从高德/腾讯复制的位置要能直接用 | 折叠区支持整段粘贴分享链接：高德 `position=经度,纬度`、腾讯 `marker=coord:纬度,经度;title:`、百度 `location=纬度,经度`、苹果 `ll=`、`geo:`、以及 `25.0456, 102.7123` 这类纯数字（经度在前也能自动换回来）。解析出的名称会回填"地点名称"。 |
| 详情页要能直接导航过去 | 主按钮「导航到这里 ↗」按高德 URI 打开（`uri.amap.com/marker?position=<gcj经度>,<gcj纬度>&coordinate=gaode&callnative=1`，装有高德就唤起 App）；「其他地图」展开腾讯、苹果、百度与「复制坐标」四个入口。地址、坐标分行显示，距市中心超过 50 米才显示距离。 |
| 首页"出发点"到底有什么用 | 文案改为「设置出发点，看每家店有多远」，选过后变成「更换出发点」并给「清除」；卡片上的距离从"直线约 1.4 km"改为 `距出发点约 620 米 / 1.2 公里`，与弹窗内文案同源。 |
| 发布时选完点还要再填一遍地名 | 发布页选点后，若"地点名"还空着，自动用地图地点名回填；已填过的绝不覆盖（`draft.venue||draft.placeText` 为空才写）。 |

## 二、坐标系：只存一套，按需换算

新建 `src/domain/geo.ts`，把这件事收在一个文件里：

- **库里只存 WGS84**。浏览器 `navigator.geolocation` 与 OSM 都是 WGS84，高德/腾讯底图与链接是 GCJ-02，百度是 BD-09。写库前统一 `toWgs84()`，显示与跳转时才换算，避免同一个地点在两套坐标间来回漂移。
- 加偏用标准 `transformLatitude/Longitude` 算法；**逆算用同点一次偏移近似**，实测昆明来回误差 0.31 米（`tests/geo.test.ts` 断言 < 2 米），足够选点与导航。
- `toBd09` 必须"先 GCJ-02 再叠 BD-09"，不能拿 WGS84 直接套公式——这是本轮单测抓到的真实缺陷（原先会偏三百多米）。
- 昆明服务范围 `24.35–26.45°N / 102.1–103.75°E` 与小程序 `location.js` 的 `point()` 一致；越界不静默通过，弹窗给提示。

`navigationLinks()` 一次算出五份结果，各家拿自己需要的坐标：

```ts
{ amap:'uri.amap.com/marker?position=<gcjLng>,<gcjLat>&coordinate=gaode',
  tencent:'apis.map.qq.com/uri/v1/marker?marker=coord:<gcjLat>,<gcjLng>;title:…',
  apple:'maps.apple.com/?ll=<wgsLat>,<wgsLng>&q=…',
  baidu:'api.map.baidu.com/marker?location=<bdLat>,<bdLng>&coord_type=bd09ll',
  coordinate:'<gcjLat>, <gcjLng>' }
```

名称与地址都做了 `encodeURIComponent`，`A&B 食堂` 这类名字不会把链接截断（有用例守着）。

## 三、跟着小程序对齐的三处细节

1. **选点即回填名称**：小程序的 `chooseLocation()` 会自动带回地点名，网页版原先只存坐标，用户还得自己想名字。现在弹窗内的"地点名称"必填，从链接解析时自动写入。
2. **保留手填地址**：地图位置与手填的窗口/街区说明是两套字段（`latitude/longitude/locationName` 与 `venue/addressSummary`），改地图不动文字（服务端 `savedLocation()` 与前端提示"手填地址保持不变"口径一致）。
3. **可清除、可预览**：发布页已选点有「已选地点 · 名称 + 移除」；详情页"修改定位"与"导航到这里"分开——先看再改，不会点错就把位置挪走。

## 四、修掉的一个现有缺陷

Leaflet 弹窗卸载时仍在跑动画帧，关掉选点弹窗会抛 `Cannot read properties of undefined (reading '_leaflet_pos')`（上一轮验收里没有定位用例，所以一直没暴露）。现在卸载前先 `stop()` 再 `remove()`，并用 `alive` 标记挡住卸载后回来的点击/拖拽回调，`setView` 一律 `{animate:false}`。修复后 6 宽度 × 5 页面巡检 `pageError=0`。

## 六、没做与边界

- **高德瓦片走的是公开瓦片地址**，没有申请商用 key；如果哪天被限流，会自动回退 OSM（英文/少数中文），选点功能不受影响。要更稳需要高德开放平台 key 与配额，属于需要账号授权的动作，本轮没有做。
- **POI 搜索没做**。小程序的 `chooseLocation` 带关键词搜地点，网页版受限于没有地图 JS SDK key（高德/腾讯的 Web 服务都要 key），只能用"点地图 + 粘贴分享链接"两条路接近同样的效率。要真做搜索，得先拿到一份可用的地图 key。
- 百度坐标是"GCJ-02 再叠偏移"的一次近似，与百度官方 `bd09ll` 误差在米级；苹果地图在国内会由系统再纠偏，指向同一地点。
- 导航全部走系统浏览器/App 的 URI，不内嵌导航；微信内置浏览器对 `uri.amap.com` 的唤起行为与手机厂商有关，未逐机型验证。
- 未在 iPhone/Android/微信实体机上实测定位授权拒绝、精度波动与弱网下的底图回退；方位角、海拔、轨迹类能力不在本轮范围。
