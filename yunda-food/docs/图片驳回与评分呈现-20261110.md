# 图片驳回与评分呈现（2026-11-10）

本轮在上一轮「图片兼容与使用体验整改」基础上追加两件事：① 管理员可以驳回用户上传的**任何**图片（头像、推荐配图、黑榜照片、树洞话题配图），驳回后要求作者重新上传，被驳回的头像以默认头像显示；② 评分信息在卡片、紧凑行、格子卡与详情页都改为醒目呈现，首页排列切换按钮改回站内既有的胶囊（chip）画风。

## 一、图片驳回

### 入口

- 集中审核台 → 选中内容 → 查看态图片下方新增「照片不合规可单独驳回」区：逐张「第N张」+「确认驳回这张照片」。只对推荐 / 黑榜 / 话题开放（评价与楼层回复没有配图）。
- 用户治理 → 用户 → 「查看并管理这个用户」→ 用户资料面板新增「驳回这张头像」（当前无头像时按钮禁用）。

### 服务端语义

- 新动作 `adminRejectImage`，参数 `kind`（`food` / `caution` / `topic` / `avatar`）、`id`、`fileId`、`reason`、`clientRequestId`。
- 仅管理员可调用；理由 2～120 字；`clientRequestId` 必须 12～80 位并做幂等回执，**同一编号重放返回原结果、不重复发通知；同一编号换内容直接拒绝**。
- 未传 `id` 时按 `fileId` 反查所有者，找不到就明确提示「找不到这张照片所在的内容」。
- **不新增集合**：驳回审计写入私有事件集合 `xsyj_events`（`type:'image_rejection'`），回执写入 `image_reject_receipt_*`，作者通知复用 `xsyj_review_notifications`（`kind:'content_review'`、`tag:'changes'`、`editPath` 指向重新上传页）。
- 内容处理：配图从 `imageFileIds` / `images` 中移除，并把「被驳回照片 + 原因」追加进 `rejectedImages`（最多保留 10 条，仅作者与管理员可见）；头像则把 `avatarFileId` 置空并写入 `avatarRejected{fileId,reason,at,by}`。
- 防复用：`mediaUrl` 对已驳回文件一律拒绝签发链接；`saveFood` / `saveCaution` / `saveForumTopic` / `saveProfile` 都拒绝把同一张已被驳回的图片再次提交。

### 前端表现

- 作者编辑页/投稿页的图片区末尾出现「第N张已驳回 + 驳回说明」占位，并提示「有 N 张照片被驳回并已移除，请重新上传后再保存」。
- 头像被驳回后，资料页与「我的」显示「头像已被驳回：…」与「重新上传头像」入口；未重新上传前，全站（详情作者、评价、评论、用户主页、管理面板）统一回落到默认「食」头像。
- 三入口演示模式（`?demo=admin|student|empty`）同步实现同样的驳回语义，便于离线复验。

### 本轮发现并修复的两个真实缺口

1. **黑榜详情丢字段**：`native/cautions.js` 的 `expose()` 用字段白名单组装返回值，漏了 `rejectedImages`，导致云端驳回后作者看不到原因（本地单测直接用 DTO 造数据所以没暴露）。已补进白名单（仅作者/管理员可见）。
2. **头像驳回写库失败**：CloudBase 会把嵌套对象拆成点路径更新，而资料文档里 `avatarRejected` 初始是 `null`，Mongo 拒绝「在 null 里创建字段 'at'」。改为在事务内用刚读到的整条资料替换文档（剥掉 `_id`）写回，既避免点路径问题，也保持原子性。

## 二、评分与按钮呈现

- 详情页评分由一行浅灰小字改为高亮条：金色五颗星（与评价表单同色）+ 红色大号分数 + 「分」+ 右侧「N 人评分」，无评分时显示「— 暂无评分」。
- 卡片、紧凑行、格子卡统一新增评分胶囊「★ 4.0 · 1 人」；紧凑行放在标题与价格之间，格子卡放在价格下方，窄屏不换行、不撑破。
- 首页「卡片 / 紧凑 / 格子」排列按钮原本是浅蓝分段控件，与站内按钮画风不一致；现改为与「全部地点/校内/校外」相同的胶囊：米白底、细描边、选中为站内蓝并带 1px 硬阴影，按下有位移反馈。

## 四、边界与未验证

- 未用 iPhone / Android / 微信实体机验证相册直传、头像驳回后的实际显示与缓存刷新，均为桌面 Chromium 视口模拟。
- 驳回是「按图」处理，整条内容的审核标签（通过/退回/下架）仍是原有的集中审核动作；两者互不替代。
- 评价与楼层回复没有配图，因此审核台不提供单图驳回入口。
- 已驳回文件仍保留在云存储中（仅停止签发链接并阻止复用），便于申诉复核；如需彻底删除需另行授权清理脚本。
